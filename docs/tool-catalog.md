# Garmin Personal MCP tool catalog

The tables map all 28 GET operations in Garmin's OpenAPI 3.0.1 document (API version 1.0.0) to one tool each. The path and upstream response names come from the OpenAPI document embedded in Garmin's Swagger page. The FIT tool reuses an existing GET. The internal token exchange is `POST /personalapitoken-service/personal-api/personal-api-key/token` and has no MCP tool. [Garmin Personal Swagger](https://developer.garmin.com/gc-developer-program/personal/swagger-docs/) · [Garmin Personal API FAQ](https://developer.garmin.com/gc-developer-program/personal/personal-faq)

## Shared contract

- All dates are real calendar dates in `YYYY-MM-DD` format. Daily tools require an explicit date even where Swagger marks the underlying query optional. Range tools require both endpoints, reject reversed dates, and budget the range by counting both boundary dates. Pass the date strings through without UTC conversion. Where Garmin explicitly documents local or inclusive semantics, the rows say so. The MCP limits below are application limits, including where they match documented Garmin limits. Use multiple explicit calls for longer ranges. Only activity search has offset pagination.
- Use decimal strings for positive 64-bit IDs such as `activityId` and `mealId`. Reject values above signed int64 and preserve integer precision when reading IDs from upstream JSON. Validate argument types and reject unknown keys.
- Return structured `{data, units}` results for JSON tools. List rows use arrays within `data`, singleton rows use objects, and Garmin wrapper objects retain their named collections. The result column names the upstream DTO and the fields or groups to expose. Use explicit field projections. Exclude internal account IDs, third-party names and comments, device serials, raw media URLs, and route coordinates from output. The owner-facing profile settings projection may include the owner's display name. Preserve offsets and UTC/local distinctions on timestamps. Only publish a unit if documented or verified against a fixture. For Garmin series encoded as rows, use their column descriptors and preserve the native encoding when a column's unit is unspecified.
- Preserve empty lists as `[]` and map a documented 204 to a successful `data: null`. Omit unavailable optional metrics or retain explicit nulls. A zero is a measurement. For required response structures, a malformed body maps to `garmin_unavailable`. Apply the byte limits in [Architecture](architecture.md).
- All tools share the errors below. The last table column lists tool-specific conditions in addition to shared argument validation, authorization and upstream failures.

| Error | When returned |
| --- | --- |
| `invalid_input` | Schema validation or endpoint-specific validation fails, or Garmin returns 400 for the supplied arguments |
| `not_found` | Garmin returns 404 for a requested entity |
| `rate_limited` | Garmin returns 429, with optional `retryAfterSeconds` |
| `garmin_auth_failed` | Token exchange fails due to invalid credentials, or an upstream 401 persists after one renewal |
| `garmin_forbidden` | Garmin returns 403 |
| `garmin_unavailable` | Network failure, Garmin 5xx or unexpected upstream response |
| `timeout` | Application deadline or upstream timeout |
| `payload_too_large` | Result, archive or analysis budget exceeded |
| `corrupt_archive` / `unsupported_archive` | ZIP or FIT integrity failure / unsupported representation or no supported activity FIT |

Use MCP tool errors with `isError: true` and a stable code plus a short sanitized message. Inbound Auth0 failures occur at the HTTP boundary before MCP dispatch. Browser download errors use HTTP status codes, such as 404 for a missing activity, 410 for an expired ticket, 413 for an oversized archive detected before response start, 415 for an unsupported file representation, 429 for throttling and 502 or 504 for upstream failure or timeout. Activity search supports these additional query fields.

- `favorite` is -1 (all, default), 0 or 1. `sortOrder` is `desc` (default) or `asc`. `sortBy` is an upstream sort key such as `startLocal` (default), `name`, `distance` or `duration`. `excludeChildren` defaults to true. `search` filters name and description.
- `activityType` is a parent type key. `activitySubType` is a child type key and must belong to the parent when both are supplied. `eventType` filters event classification. Send `excludedActivitySubType` and `requiredField` as repeated parameters. Every required field must be present in matching records.
- `startDate` and `endDate` optionally bound activity start dates inclusively in activity-local time. If both are supplied, allow up to 366 days per call. An omitted bound stays open.
- Inclusive nonnegative integer limits include `minDistance` and `maxDistance` (m), `minDuration` and `maxDuration` (timer s), `minElapsedDuration` and `maxElapsedDuration` (elapsed s), `minElevation` and `maxElevation` (gain in m), `lowerMaxDepth` and `upperMaxDepth` (cm), `minBottomTime` and `maxBottomTime` (s), and `minAvgPower` (W). Optional `decoDive` is boolean.
- Supply `upperLatitude`, `lowerLatitude`, `rightLongitude` and `leftLongitude` together in decimal degrees. Validate latitude within ±90 and longitude within ±180. Garmin can reject an oversized box. Activity changes between page requests can shift the offset, and a full final page can be followed by an empty page. ## FIT analysis

`analyze_activity_fit` takes a required `activityId`, optional zero-based `lapOffset` (default 0), and optional `lapLimit` (default 25, maximum 50). It fetches the original activity archive through the same Garmin GET used by `download_activity`. It operates on Garmin bytes fetched for the authorized owner and accepts no external archive URL.

- Use an in-memory ZIP reader with integrity checks and an official Garmin FIT JavaScript SDK decoder. Initial limits are 16 MiB compressed, 32 MiB total inflated, 16 MiB per FIT member, 32 ZIP members and 32 sessions. Enforce the byte limits during reading and inflation and terminate decoding at the request deadline. Check ZIP integrity for the selected members, reject unsupported compression or encrypted entries, skip directory entries, and never extract files to disk.
- Detect FIT members by header and verify length and CRC with the FIT SDK. Decode activity FIT files in archive order and sessions/laps in file order. Ignore non-activity members. A valid archive without activity FIT data is `unsupported_archive`. Malformed ZIP, corrupt selected FIT, or decoder integrity errors return `corrupt_archive`. Oversized input, output or session count returns `payload_too_large`.
- Return `{activityId, sessions, laps, totalLaps, nextLapOffset, units}`. Each session has a stable zero-based index within the result, sport, available UTC start, distance in m, timer and elapsed time in s, average speed in m/s, and recorded average and maximum heart rate in bpm, cadence with the FIT sport-specific unit, and power in W. Each lap uses the same available metrics with a lap index and session index when the FIT lap/session relationship is known. Use the FIT session's lap index/count metadata when available. Preserve FIT running cycles per minute unless a documented conversion to steps per minute is applied. Derive running pace in s/km from positive average speed or positive distance and timer duration. Omit unavailable metrics or uncertain links. Return null for `nextLapOffset` once all laps are covered. [Garmin FIT JavaScript SDK](https://github.com/garmin/fit-javascript-sdk)
